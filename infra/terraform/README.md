# Terraform — AWS ECS Fargate deployment

Production-shaped IaC skeleton that runs the API + queue worker on **ECS
Fargate**, behind an **ALB**, with **RDS Postgres** (multi-AZ), **ElastiCache
Redis** (failover), an **S3** uploads bucket, **ECR**, and **Secrets Manager**.
It maps 1:1 onto the app: the same image runs as `node dist/main` (API,
`PROCESS_QUEUES=false`) and `node dist/worker` (`PROCESS_QUEUES=true`), and the
ALB health check hits `/health/ready` — the readiness probe added in Phase 1.

> Status: **skeleton, validated** (`terraform validate` passes). It is intended
> as a reviewed starting point, not a turnkey apply — see *Before production*.

## Layout

| File | Contents |
|------|----------|
| `versions.tf`  | Terraform + provider pins; commented S3 state backend |
| `variables.tf` | Inputs (region, sizes, counts, cert ARN, …) |
| `main.tf`      | Provider, default tags, AZ/subnet locals |
| `network.tf`   | VPC, public/private subnets, IGW, per-AZ NAT, routes, security groups |
| `data.tf`      | Secrets, RDS, ElastiCache, S3, ECR |
| `ecs.tf`       | Cluster, IAM (exec + task roles), ALB + listeners, task defs, services |
| `outputs.tf`   | ALB DNS, ECR URL, endpoints |

## Topology

```
  Internet ── ALB (public subnets, :443) ──► API service (private subnets)
                                              worker service (private, no ALB)
                       │                              │
            RDS Postgres (private, multi-AZ)   ElastiCache Redis (private, failover)
                       │
              S3 uploads ◄── task IAM role (no static keys)
```

Secrets (`DB_PASSWORD`, `JWT_SECRET`) are generated by Terraform, kept in Secrets
Manager, and injected into the task via the **execution role**. The app's own S3
access uses the **task role** — the app omits `STORAGE_ACCESS_KEY/SECRET` in
prod and resolves the role through the SDK's default credential chain.

## Usage

```bash
cd infra/terraform
terraform init
terraform plan  -var image_tag=$(git rev-parse --short HEAD) -var acm_certificate_arn=<arn>
terraform apply -var image_tag=$(git rev-parse --short HEAD) -var acm_certificate_arn=<arn>

# Deploy a new version: push the image to the ECR URL (output), then re-apply
# with the new image_tag (ECS does a rolling, health-checked replacement).
```

## Before production

- **Remote state:** create the S3 bucket + DynamoDB lock table and enable the
  `backend "s3"` block in `versions.tf` (don't keep state local for a team).
- **TLS:** supply a real `acm_certificate_arn`; the HTTP listener already 301s to
  HTTPS.
- **Redis in transit:** flip `transit_encryption_enabled = true` and switch the
  app to `rediss://`.
- **Autoscaling:** add `aws_appautoscaling_*` target/policies on the API service
  (CPU/RPS) — the deployment is already rolling and health-checked.
- **PgBouncer:** for many replicas, front RDS with PgBouncer (see
  `../pgbouncer/` and `../../docs/architecture/scaling.md`) and point `DB_HOST`
  at it; add read replicas via `DB_REPLICA_HOSTS`.
- **Cost note:** per-AZ NAT gateways and multi-AZ RDS/Redis are billed hourly.
